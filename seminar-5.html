Why JavaScript?

A web page has three layers. HTML gives it structure, CSS gives it style, and JavaScript gives it behaviour. It runs in the user's browser, so it can react instantly, with no round trip to your Flask server.

One big difference: JavaScript does not wait

Python runs line by line and input() blocks until the user types. JavaScript in the browser must never freeze the page, so slow things (timers, network requests) are handed off with a callback and the script keeps going. Read the output order carefully; it is the key to AJAX later.

2Whack-a-Mole: JavaScript meets the DOM

The browser turns your HTML into a tree of objects called the Document Object Model. JavaScript can find any node, change it, add to it or remove it, and react to the user's clicks. That is all a web game is.

3jQuery: say more with less

The DOM API is powerful but wordy. jQuery is a small library that wraps it in short, chainable commands, and it is what the seminar and lab use. One line of jQuery often replaces four lines of plain JavaScript.

3.1 The idea

  1. Load the library: <script src="https://code.jquery.com/jquery-3.7.1.min.js"></script> (before your own script).
  2. Use $ to select elements with a CSS selector, then call a method to act on them: $("selector").action()
  3. Wrap your code in $(function () { ... }) so it runs once the page is ready.
$(function () {                          // run when the DOM is ready
  $("#greet").on("click", function () {  // find, then listen
    $("#card").text("Hello!").addClass("highlight");   // find, then chain two actions
  });
});

    4AJAX & JSON: talking to the server

    So far every score vanishes when you refresh. To keep scores, the page must talk to the server without reloading. That technique is AJAX, and it is what turns a collection of pages into a single-page application.

    4.1 Two ways to build a page

    Server-side rendering (your Flask templates so far)

    1. Browser asks for /blog
    2. Flask runs render_template(...)
    3. Server sends finished HTML
    4. Browser replaces the whole page

    Client-side rendering (AJAX)

    1. Page is already loaded
    2. JavaScript asks for /api/scores in the background
    3. Flask runs jsonify(...), sends JSON data
    4. JavaScript builds only the HTML it needs and updates that part of the page

    AJAX = Asynchronous JavaScript And XML (today it carries JSON, not XML). Asynchronous means the page stays usable while the request is in flight, and your code runs later in a callback, exactly like the setTimeout in Section 1.

    The #1 AJAX mistakeYou cannot write let r; $.ajax({... success: d => r = d}); console.log(r);. The request has not come back yet when console.log runs, so r is still undefined. Everything that needs the data goes inside the callback.

@app.route("/api/scores", methods=["GET"])
def get_scores():
    limit = request.args.get("limit", 5, type=int)
    rows = Score.objects.order_by("-score")[:limit]
    return jsonify({"scores": [r.to_dict() for r in rows], "count": Score.objects.count()})

@app.route("/api/scores", methods=["POST"])
def add_score():
    payload = request.get_json(silent=True) or request.form    # JSON body or form body
    name, score = payload.get("name", "").strip(), payload.get("score")
    if not name:
        return jsonify({"error": "Name is required"}), 400
    Score(name=name, score=int(score)).save()
    rank = Score.objects(score__gt=int(score)).count() + 1
    return jsonify({"ok": True, "rank": rank})

    5Chart.js: turn data into pictures

    Chart.js draws charts on an HTML <canvas>. You describe what to draw (type, labels, numbers) as a plain object, and it handles axes, colours, animation and responsiveness.

    5.1 Six steps to a chart

    1. Put a canvas in your HTML: <canvas id="myChart"></canvas>
    2. Load the library: <script src="https://cdn.jsdelivr.net/npm/chart.js"></script>
    3. Prepare labels (the x-axis, a list of strings), datasets (a list of objects, each with a label and a list of numbers in data) and options.
    4. Get the canvas element.
    5. Call new Chart(canvas, { type, data: { labels, datasets }, options }).

    Python parallel: this is a plt.bar(labels, values) in matplotlib, except the "figure" is described as a dict and drawn live in the page, so it is interactive (hover for tooltips) and you can feed it from AJAX.

    Debugging checklist

    1. Press F12 → Console. Read the first red error; the rest are usually side effects.
    2. x is not defined / $ is not defined: a typo, a missing <script src>, or the library loads after your code.
    3. Cannot read properties of null: your selector found nothing (wrong id? script runs before the element exists?).
    4. Nothing happens on click: console.log("clicked") inside the handler to prove it runs.
    5. AJAX shows undefined: you are using the data outside the callback.
    6. Network tab: is the request sent? What status? What does the response look like?
