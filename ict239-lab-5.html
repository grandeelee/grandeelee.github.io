Step 1 - Prepare the JSON endpoints

A JSON endpoint is an ordinary Flask route, but it returns data instead of an HTML page. Browsers and JavaScript can then fetch just the data they need.

1.1 Create the API blueprint

Create a new file controllers/api.py. It follows the same pattern as shop.py and auth.py.

controllers/api.py
from flask import Blueprint, jsonify

from models.product import Product

api = Blueprint("api", __name__)  # endpoints become api.productDetail, api.revenue, api.revenuePage


@api.route("/api/products/<product_id>")
def productDetail(product_id):
    """One product as JSON - called by the hover popup on the shop page."""
    product = Product.getProduct(product_id)
    if not product:
        return jsonify({"error": "Product not found"}), 404
    return jsonify({
        "id": str(product.id),
        "name": product.name,
        "description": product.description,
        "price": product.price,
    })

Points to note:

  • jsonify() converts a Python dict to a JSON response and sets the Content-Type: application/json header for you.
  • The product comes from MongoDB via the existing Product.getProduct(). It returns None for an unknown or malformed id, so we answer with 404 and a small JSON error. The status code is the second value in the returned tuple.
  • A MongoEngine document is not JSON-serialisable by itself, so we pick the fields to expose. product.id is an ObjectId, which is why it is wrapped in str().

Step 2 - Product details popup with $.ajax

AJAX lets JavaScript request data from the server in the background and update part of the page, without a reload. You will use jQuery's low-level $.ajax() function only (not $.get, $.getJSON or fetch), so that the options are explicit:

OptionMeaning
urlthe endpoint to call
methodHTTP method, "GET" here
dataTypewhat we expect back; "json" makes jQuery parse it into a JavaScript object
successcallback that runs with the parsed data when the call succeeds (2xx)
errorcallback that runs when the call fails (e.g. the 404 above, or the server is down)

2.1 Load jQuery and add a scripts block to the base template

jQuery is not in the project yet. Add it to base.html just before </body>, after the Bootstrap script. The empty {% block scripts %} lets each page add its own JavaScript, loaded after jQuery.

templates/base.html
  <!-- Bootstrap JS (needed for the collapsing navbar on phones) -->
  <script src="https://cdn.jsdelivr.net/npm/bootstrap@5.0.2/dist/js/bootstrap.bundle.min.js"></script>
  <!-- jQuery: the full build (the "slim" build has no $.ajax) -->
  <script src="https://code.jquery.com/jquery-3.7.1.min.js"></script>
  {% block scripts %}{% endblock %}
</body>

Watch out: jQuery also ships a "slim" build (jquery-3.7.1.slim.min.js). It leaves out the AJAX module, so $.ajax would be undefined. Use the full build above.

2.2 Give each product card the URL of its detail endpoint

The page needs to know which endpoint belongs to which card. Let Flask build the URL with url_for and store it in a data- attribute, which jQuery reads with .data(). In shopping.html, change the card's opening <div>:

templates/shopping.html
<div class="card h-100 product-card rounded-0"
     data-detail-url="{{ url_for('api.productDetail', product_id=product.id) }}">

Reload the shop page and use "View source" to confirm each card now has a data-detail-url such as /api/products/6650....

2.3 Add the popup container and the script

At the bottom of shopping.html, after the closing </main> and still inside {% block content %}, add one shared popup element. Then add a {% block scripts %} after {% endblock %} of the content block:

templates/shopping.html
</main>

<!-- One shared popup; the script moves it and fills it in -->
<div id="product-popup" class="product-popup" style="display:none;"></div>
{% endblock %}

{% block scripts %}
<script>
$(function () {
  const $popup = $("#product-popup");

  function showPopup(html) {
    $popup.html(html).show();
  }

  $(".product-card").on("mouseenter", function (event) {
    const url = $(this).data("detail-url");
    showPopup("Loading...");
    $.ajax({
      url: url,
      method: "GET",
      dataType: "json",
      success: function (product) {
        // .text() on every field: never inject server data as raw HTML
        const $box = $("<div>");
        $("<strong>").text(product.name).appendTo($box);
        $("<p class='mb-1'>").text(product.description).appendTo($box);
        $("<span>").text("$" + product.price.toFixed(2)).appendTo($box);
        $popup.empty().append($box).show();
      },
      error: function () {
        showPopup("Could not load product details.");
      }
    });
  });

  $(".product-card").on("mousemove", function (event) {
    $popup.css({ left: event.pageX + 15, top: event.pageY + 15 });
  });

  $(".product-card").on("mouseleave", function () {
    $popup.hide();
  });
});
</script>
{% endblock %}

Read the script through. It does four things:

  1. mouseenter on a card: show "Loading...", then call the endpoint with $.ajax.
  2. success: build the popup content from the returned JSON object (product.name, product.description, product.price).
  3. mousemove: keep the popup next to the cursor.
  4. mouseleave: hide it.

Why .text() and not string concatenation into .html()? Product names and descriptions are data. If they contained <script> and were injected as HTML, the script would run in every visitor's browser (cross-site scripting). .text() always treats the value as plain text.

2.4 Style the popup

Step 3 - Revenue charts with AJAX and Chart.js

You will build the page /revenue. The route only serves an HTML shell; the numbers arrive afterwards through $.ajax from /api/revenue, and are drawn with Chart.js (the same library as in the seminar's exercise.html).

3.1 Add the page route

In controllers/api.py, change the import on the first line to include render_template, and add the route at the bottom:

controllers/api.py
from flask import Blueprint, jsonify, render_template

# ... existing routes ...

@api.route("/revenue")
def revenuePage():
    """The HTML page; the numbers are fetched by JavaScript afterwards."""
    return render_template("revenue.html")

3.3 Create the page template

Create templates/revenue.html. First the layout, with two <canvas> elements that Chart.js will draw on:

templates/revenue.html
{% extends "base.html" %}

{% block title %}Revenue{% endblock %}

{% block content %}
<main class="container my-5">
  <h1 class="h3 mb-4">Revenue analytics</h1>

  <div class="row g-4">
    <div class="col-12 col-lg-5">
      <div class="card rounded-0 p-3">
        <h2 class="h6">Share of revenue by category</h2>
        <canvas id="shareChart"></canvas>
      </div>
    </div>
    <div class="col-12 col-lg-7">
      <div class="card rounded-0 p-3">
        <h2 class="h6">Monthly revenue by category</h2>
        <canvas id="monthlyChart"></canvas>
      </div>
    </div>
  </div>
</main>
{% endblock %}

Then add the script below it (still in the same file). Chart.js is loaded from a CDN, and this page's script runs after jQuery because of the scripts block from Step 2.

templates/revenue.html
{% block scripts %}
<script src="https://cdn.jsdelivr.net/npm/chart.js@4.4.1/dist/chart.umd.min.js"></script>
<script>
$(function () {
  $.ajax({
    url: "{{ url_for('api.revenue') }}",
    method: "GET",
    dataType: "json",
    success: function (data) {
      drawShareChart(data);
      drawMonthlyChart(data);
    },
    error: function () {
      $("main").append("<p class='text-danger'>Could not load revenue data.</p>");
    }
  });

  function drawShareChart(data) {
    const totals = data.categories.map(function (c) {
      return c.monthly.reduce(function (sum, v) { return sum + v; }, 0);
    });
    new Chart($("#shareChart"), {
      type: "doughnut",
      data: {
        labels: data.categories.map(function (c) { return c.name; }),
        datasets: [{ data: totals }]
      }
    });
  }

  function drawMonthlyChart(data) {
    new Chart($("#monthlyChart"), {
      type: "bar",
      data: {
        labels: data.months,
        datasets: data.categories.map(function (c) {
          return { label: c.name, data: c.monthly };
        })
      },
      options: {
        scales: {
          x: { stacked: true },
          y: { stacked: true, title: { display: true, text: data.currency } }
        }
      }
    });
  }
});
</script>
{% endblock %}

3.4 How it works

  • One request, two charts. The data is fetched once. In success, the same object is passed to two functions.
  • Doughnut needs one number per category, so the monthly values are totalled with reduce. This is client-side processing of the JSON.
  • Stacked bar needs one dataset per category and one value per month. data.categories.map(...) reshapes the JSON into Chart.js datasets. Setting stacked: true on both axes stacks the bars.
  • Compare this with the seminar's exercise.html: labels and datasets are the same structure, but here the values come from the server instead of being typed in.

Extra challenges

  1. Change the format. Change type: "doughnut" to "pie", then to "polarArea". Change the monthly chart so that it is a "line" chart with stacked removed. Notice that only type and options change; the data stays the same.
  2. Add a total line. In drawMonthlyChart, add a dataset of type "line" whose values are the total across categories for each month (a mixed bar + line chart).
  3. Add a format selector. Add a <select> with Doughnut / Pie / Bar above the first chart. When it changes, destroy the old chart (chart.destroy()) and redraw with the chosen type, without calling the server again (keep the data in a variable).
  4. Colours and labels. Give each category a fixed colour via backgroundColor, and format tooltips as S$ 4,200 using options.plugins.tooltip.callbacks.label.
  5. Price in the popup. Cache each product's JSON in a JavaScript object keyed by id so that hovering the same card again does not call the server a second time.

Summary

  • An endpoint that returns JSON is just a route using jsonify(); the same data can feed many different views.
  • $.ajax({url, method, dataType, success, error}) fetches JSON without reloading, and the page is updated in the callback (client-side rendering).
  • Insert server data into the page with .text(), not as raw HTML.
  • Chart.js only needs type, labels and datasets; JSON from the server is reshaped into that form.
