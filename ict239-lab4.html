Part A · Product search & filtering

Plain keyword arguments to .objects() are already ANDed together — Product.objects(price__gt=20, price__lt=60, name__ne="Notebook") needs no Q at all. Q only becomes necessary for an OR, a NOT on a whole group, or when a query is assembled conditionally out of pieces that are themselves an OR — which is exactly the situation filterProducts below is in.

app/models/product.py — add these methods

models/product.py
from mongoengine import Q
from mongoengine.errors import ValidationError
from app import db


class Product(db.Document):
    meta = {"collection": "products"}
    name = db.StringField(required=True, max_length=60)
    description = db.StringField(max_length=300)
    price = db.FloatField(required=True, min_value=0)

    @staticmethod
    def getProduct(product_id):
        try:
            return Product.objects(pk=product_id).first()
        except ValidationError:
            return None

    @staticmethod
    def getAllProducts():
        return Product.objects()

    @staticmethod
    def createProduct(name, description, price):
        return Product(name=name, description=description, price=price).save()

    # ---- Part A: advanced querying -----------------------------------------

    @staticmethod
    def getByPriceRange(min_price=None, max_price=None):
        filters = {}
        if min_price is not None:
            filters["price__"] = min_price
        if max_price is not None:
            filters["price__"] = max_price
        return Product.objects(**filters)

    @staticmethod
    def _applySort(queryset, sort):
        sort_map = {
            "price_asc": "price",
            "price_desc": "",
            "name_asc": "name",
        }
        return queryset.(sort_map.get(sort, "name"))  # "name" is the default order

    @staticmethod
    def search(keyword):
        return Product.objects(Q(name__=keyword) | Q(description__=keyword))

    @staticmethod
    def filterProducts(keyword=None, min_price=None, max_price=None, sort=None):
        query = Q()
        if keyword:
            query  (Q(name__icontains=keyword) | Q(description__icontains=keyword))
        if min_price is not None:
            query &= Q(price__=min_price)
        if max_price is not None:
            query &= Q(price__=max_price)

        results = Product.objects(query)
        return Product._applySort(results, sort)
  • getByPriceRange and search are the two "single technique" building blocks (a comma-separated **filters dict for the optional range, Q(...) | Q(...) for OR-matching two fields). filterProducts is where they get combined, which is the actual capstone requirement — a single query built from zero to four independent, optional conditions.
  • _applySort centralises the "what happens with an unrecognised or missing sort value" decision, so filterProducts never has to special-case a bad sort argument.
  • Each filter line only gets added to the query when its value is not None — this optional-filter pattern is what makes every parameter independently optional. Consider what would go wrong if that check were removed.

controllers/shop.py
from flask import Blueprint, render_template, redirect, url_for, flash, request
from flask_login import login_required, current_user

from models.product import Product
from models.cart import CartItem

shop = Blueprint("shop", __name__)


@shop.route("/")
def home():
    """Insert the sample catalogue the first time the shop is opened, then list the products."""
    if Product.objects.count() == 0:
        samples = [
            ("Linen Shirt", "Breathable, relaxed fit.", 79.0),
            ("Canvas Tote", "Sturdy everyday bag.", 35.5),
            ("Ceramic Mug", "Hand-glazed, 350 ml.", 18.0),
            ("Wool Beanie", "Soft merino blend.", 24.9),
            ("Leather Wallet", "Slim, full-grain leather.", 55.0),
            ("Cotton Socks (3 pack)", "Everyday crew socks.", 15.0),
            ("Desk Lamp", "Warm light, adjustable arm.", 48.0),
            ("Notebook", "A5, 120 pages, dotted.", 9.5),
        ]
        for name, description, price in samples:
            Product.createProduct(name, description, price)

    keyword = request.args.get("keyword", "").strip() or None
    sort = request.args.get("sort") or None

    min_price = request.args.get("min_price")
    min_price = float(min_price) if min_price else None

    max_price = request.args.get("max_price")
    max_price = float(max_price) if max_price else None

    products = Product.filterProducts(keyword=keyword, min_price=min_price, max_price=max_price, sort=sort)
    return render_template(
        "shopping.html",
        products=products,
        keyword=keyword or "",
        min_price=request.args.get("min_price", ""),
        max_price=request.args.get("max_price", ""),
        sort=sort or "",
    )

The raw query-string values (not the parsed floats) are passed back into the template purely so the filter bar can redisplay what was searched for — the same "sticky form" idea as form.field.data for the WTForms login/register forms in Step 4 of the walkthrough, done here by hand because this is a plain GET form, not a FlaskForm.

Part B · Filtering the cart through a reference field

This reuses CartItem exactly as built in Step 7/8 of the walkthrough — no new collection, no new model. The only new idea: CartItem.product is a ReferenceField(Product), so MongoDB only stores that product's _id inside each CartItem document. Filtering the cart by price means filtering by a field that lives on a different collection, reached through that reference.

Why this needs a different technique than Part A. Product.objects(price__gte=20) works because price is a field on Product itself. There is no price field on CartItem — only a product reference and a quantity. So CartItem.objects(price__gte=20) does not work.

Approach 1 — filter in Python

Fetch the cart as normal, then keep only the lines whose item.product.price is in range:

plain python
# app/models/cart.py
@staticmethod
def filterCart(user, min_price=None, max_price=None):
    items = CartItem.getCartItems(user)
    if min_price is not None:
        items = [i for i in items if i.product.price >= min_price]
    if max_price is not None:
        items = [i for i in items if i.product.price <= max_price]
    return items

Simple, and fine for a cart, which will only ever hold a handful of lines per user.

Approach 2 — push the filter into the query, through the reference

First find the matching Products, then ask MongoEngine to only return CartItems whose product is one of those, using the membership operator from the cheat sheet above:

reaches through ReferenceField
# app/models/cart.py
from models.product import Product

@staticmethod
def filterCart(user, min_price=None, max_price=None):
    product_filters = {}
    if min_price is not None:
        product_filters["price__"] = min_price
    if max_price is not None:
        product_filters["price__"] = max_price

    if product_filters:
        matching_products = Product.objects(**product_filters)
        return CartItem.objects(user=user, product__=matching_products)
    return CartItem.objects(user=user)

This works because MongoEngine accepts a queryset (or list) of documents on the right-hand side of that operator and matches against their _ids under the hood. Contrast the two approaches explicitly: Approach 2 issues two queries but lets MongoDB do the filtering; Approach 1 issues one query but filters in Python afterwards. For a cart (small, per-user) either is acceptable — the point is recognising that a ReferenceField is not itself queryable by the referenced document's fields.

Sorting the cart

.order_by("product__price") is not supported here for the same reason: MongoDB only sees the stored _id, not the referenced document's fields, so it cannot sort by them at the database level. To sort the cart by price or subtotal, sort in Python after fetching:

models/cart.py
@staticmethod
def getCartItemsSorted(user, sort=None):
    items = list(CartItem.getCartItems(user))
    if sort == "price_asc":
        items.sort(key=lambda i: i.product.price)
    elif sort == "price_desc":
        items.sort(key=lambda i: i.product.price, reverse=True)
    elif sort == "subtotal_desc":
        items.sort(key=lambda i: i.subtotal, reverse=True)
    return items

order_by() only ever sorts by fields actually stored on that document (as in Part A, where price lives directly on Product); sorting by a referenced document's field has to happen in Python, using the same dereferencing (item.product.price) that CartItem.subtotal already relies on in the walkthrough.

app/controllers/shop.py — updated cart() route

controllers/shop.py
@shop.route("/cart")
@login_required
def cart():
    min_price = request.args.get("min_price")
    min_price = float(min_price) if min_price else None
    max_price = request.args.get("max_price")
    max_price = float(max_price) if max_price else None
    sort = request.args.get("sort") or None

    if min_price is not None or max_price is not None:
        items = CartItem.filterCart(current_user, min_price, max_price)
    else:
        items = CartItem.getCartItems(current_user)

    if sort:
        items = sorted(
            items,
            key=lambda i: i.product.price if "price" in sort else i.subtotal,
            reverse=sort.endswith("_desc"),
        )

    total = sum(item.subtotal for item in items)
    return render_template(
        "cart.html",
        items=items,
        total=total,
        min_price=request.args.get("min_price", ""),
        max_price=request.args.get("max_price", ""),
        sort=sort or "",
    )

total is still computed after filtering, over whatever subset of items is currently shown — so the total on screen always matches the rows on screen, the same "what you see adds up" invariant the walkthrough's unfiltered cart already had.

Checkpoint B — expected behaviour

  1. Add three or four products spanning a wide price range to the cart (reuse the existing Add button from Step 7 — nothing about adding to the cart changes).
  2. /cart with no query string → every line, in insertion order, total = sum of all subtotals (unchanged from the walkthrough).
  3. /cart?min_price=20&max_price=60 → only the lines whose product price (not quantity or subtotal) falls in that range; the total updates to match only the visible rows.
  4. /cart?sort=price_desc → rows re-ordered highest unit price first; /cart?sort=subtotal_desc → ordered by quantity × price instead.
  5. Combine min_price, max_price and sort in one URL → filtering and sorting both apply together.
  6. Set min_price above every item's price → the "No cart items match that price range" message, with a "Clear filters" link, not an empty table or a crash.
  7. Clearing the filters (visiting plain /cart) still shows the full, unfiltered cart — db.cart_items.find() in mongosh still shows every document regardless of what the last filter was.
