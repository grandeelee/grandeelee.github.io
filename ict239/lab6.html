What you will deploy

The Essentials shop from Lab 5, adapted so it needs no database, plus an admin page with live traffic charts. The same shop exists twice:

Download seminar-6-material.zip and unzip it. You get both folders below.

FolderFrameworkStart command inside the container
app/Flask + Flask-Login + Flask-WTFgunicorn app:app
app-fastapi/FastAPI + Jinja2 + WTFormsuvicorn main:app

How Cloud Run works, in one picture

Your code + Dockerfile→ Cloud Build Container image (Artifact Registry)→ Cloud Run service→ https://….run.app
  • Cloud Run runs containers. You give it a container image, it gives you an HTTPS URL, and it starts or stops copies of the container depending on traffic.
  • When nobody visits for a while it scales to zero: the container is stopped and you pay nothing. The next visitor waits a second or two while a new container starts (a cold start).
  • The container must listen on the port given in the PORT environment variable (8080 by default) on 0.0.0.0, not 127.0.0.1.

Why there is no database in this version

A container's disk is thrown away every time the container stops, and a local MongoDB would vanish with it. So the data is split into two kinds:

DataWhere it livesSurvives a restart?
Products, revenue figures, the 3 starter usersJSON files in data/, baked into the imageYes - they are part of the code
Newly registered users, shopping carts, the traffic logPython dictionaries in memoryNo - gone when the container stops
Consequence: memory is private to each container. If Cloud Run started two copies, a user who registered on copy A would not exist on copy B, and the admin page would only show half the traffic. That is why Step 5 uses --max-instances 1 and why each Dockerfile runs a single worker process. For a real shop you would swap the dictionaries for a managed database (Firestore, Cloud SQL, or MongoDB Atlas).

Step 0 - Prerequisites

  1. A Google account.
  2. A billing account attached to the project (a credit/debit card is required, even for the free tier). Cloud Run has a monthly free allowance (at the time of writing: 2 million requests, 180,000 vCPU-seconds, 360,000 GiB-seconds) that a lab app will not come close to, but check the current pricing page. New accounts also get free trial credit.
  3. The gcloud CLI. Either:
    • install it from cloud.google.com/sdk/docs/install, then check with gcloud --version; or
    • use Cloud Shell in the browser, where gcloud is already installed and logged in. Upload or git clone the unzipped app and app-fastapi folders into it.
  4. You do not need Docker installed for this guide. Cloud Build builds the image for you in the cloud.

Step 1 - Run it on your own computer first

Always make sure the app works locally before blaming the cloud.

cd app
python3 -m venv venv
. venv/bin/activate
pip install -r requirements.txt
sh start.sh                  # http://127.0.0.1:5000

Log in as poh@abc.com / 12345 to shop, or admin@abc.com / 12345 to see the Admin link in the navbar. For the FastAPI version do the same inside app-fastapi.

Checkpoint: you can add items to the cart, and the Admin page draws charts that move when you click around the shop in another tab.

Step 2 - Read the Dockerfile

Each app folder contains a Dockerfile, the recipe for the container image.

app/Dockerfile
# start from a small Python image
FROM python:3.12-slim

ENV PYTHONUNBUFFERED=1 PYTHONDONTWRITEBYTECODE=1
WORKDIR /app

# requirements first, so Docker caches the pip install layer
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# then the code and data/
COPY . .

CMD exec gunicorn --bind 0.0.0.0:${PORT:-8080} --workers 1 --threads 8 --timeout 0 app:app
PartWhy
${PORT:-8080}Cloud Run sets PORT; we fall back to 8080 elsewhere.
0.0.0.0Listen on all interfaces so traffic from outside the container reaches the app.
--workers 1 --threads 8One process (so one shared memory), eight threads for concurrent requests.
gunicorn, not flask runThe Flask dev server is for development only. Gunicorn is a production server.
.dockerignoreKeeps venv/, __pycache__/ out of the image.

The FastAPI Dockerfile is the same idea with uvicorn main:app --proxy-headers --forwarded-allow-ips='*'. The proxy flags make the app trust Cloud Run's X-Forwarded-Proto header so it knows visitors arrive over HTTPS.

Step 3 - Create a Google Cloud project

# log in (opens a browser window)
gcloud auth login

# project ids are global and lowercase; pick your own suffix
gcloud projects create ict239-shop-yourname --name="ICT239 shop"

# make it the default for every later command
gcloud config set project ict239-shop-yourname

# a region close to you: asia-southeast1 = Singapore
gcloud config set run/region asia-southeast1

Now attach billing. In the console open Billing → Account management, choose your project and link a billing account. Or from the command line:

gcloud billing accounts list
gcloud billing projects link ict239-shop-yourname --billing-account=XXXXXX-XXXXXX-XXXXXX
While you are in the console, create a budget alert (Billing → Budgets & alerts), for example SGD 5, so a mistake cannot become a surprise bill.

Step 4 - Enable the services

Google Cloud keeps services switched off until you ask for them. Deploying from source needs three:

gcloud services enable run.googleapis.com \
                       cloudbuild.googleapis.com \
                       artifactregistry.googleapis.com
APIWhat it does for you
runCloud Run itself
cloudbuildBuilds your Dockerfile into an image in the cloud
artifactregistryStores the built image

This takes about a minute.

Step 5 - Deploy

Generate a random secret for signing login cookies, then deploy from inside the app folder:

cd app

SECRET=$(python3 -c "import secrets; print(secrets.token_hex(32))")

gcloud run deploy essentials-shop \
  --source . \
  --region asia-southeast1 \
  --allow-unauthenticated \
  --max-instances 1 \
  --set-env-vars "SECRET_KEY=$SECRET,ADMIN_PASSWORD=choose-a-strong-one"
FlagMeaning
essentials-shopThe service name (part of the URL).
--source .Upload this folder, build the Dockerfile with Cloud Build, push the image, deploy it. One command instead of four.
--allow-unauthenticatedMake the site public. Without it every request needs a Google identity token and visitors get 403 Forbidden.
--max-instances 1Never run more than one container, so in-memory users, carts and traffic stay in one place (see Step 0).
SECRET_KEYSigns the session cookie. Without it the app falls back to a public default that anyone could use to forge a login.
ADMIN_PASSWORDReplaces the seeded password 12345 for admin@abc.com. The admin page is on the public internet, so do not leave the default.

The first time, gcloud asks two questions:

Deploying from source requires an Artifact Registry Docker repository ... Do you want to continue (Y/n)?   y
Allow unauthenticated invocations to [essentials-shop] (y/N)?   (skipped if you passed the flag)

The build takes 2-4 minutes. At the end you get:

Service [essentials-shop] revision [essentials-shop-00001-abc] has been deployed and is serving 100 percent of traffic.
Service URL: https://essentials-shop-123456789.asia-southeast1.run.app
Passwords and keys in --set-env-vars are visible to anyone with access to the project. Fine for a lab; for real projects store them in Secret Manager and attach with --set-secrets. Avoid commas in values, since commas separate variables.

Step 6 - Try it and watch the live traffic

  1. Open the Service URL. The shop loads with 8 products.
  2. Register a new account, log in, add things to the cart. Hover a product to see the AJAX popup.
  3. Log out and log in as admin@abc.com with your ADMIN_PASSWORD. Click Admin.
  4. Press Simulate 30 visits and watch the line chart, route bars and status doughnut update every 2 seconds. Visit /no-such-page to produce a 404 and see it turn up in the 4xx slice.
  5. Log in as poh@abc.com and open /admin: you should get 403 Admins only.
Checkpoint: after a few minutes of no visits, reload the Admin page. The totals reset to 0 because Cloud Run scaled the container to zero and started a fresh one. That is the in-memory trade-off from Step 0, not a bug.

To keep one container warm (costs money, roughly a few dollars a month for the smallest size) you could add --min-instances 1. It is not needed for this lab.

Step 7 - Change the code and redeploy

Edit something, for example a product price in data/products.json or the footer text, then run the same deploy command again. A flag you leave out keeps its previous value, so a short version is enough:

cd app
gcloud run deploy essentials-shop --source . --region asia-southeast1

Each deploy creates a new revision. Cloud Run switches traffic to it once it is healthy. If it is broken, roll back instantly:

gcloud run revisions list --service essentials-shop --region asia-southeast1
gcloud run services update-traffic essentials-shop --region asia-southeast1 \
        --to-revisions essentials-shop-00001-abc=100

Step 8 - Logs and settings

# the last 50 log lines (gunicorn / uvicorn access log and any Python errors)
gcloud run services logs read essentials-shop --region asia-southeast1 --limit 50

# URL, env vars, scaling and the current revision
gcloud run services describe essentials-shop --region asia-southeast1

# just the URL
gcloud run services describe essentials-shop --region asia-southeast1 --format='value(status.url)'

# change an env variable without rebuilding
gcloud run services update essentials-shop --region asia-southeast1 --update-env-vars ADMIN_PASSWORD=new-one

The console equivalent is console.cloud.google.com/run → click the service → tabs Metrics, Logs, Revisions. The Metrics tab shows the same request counts as your admin page, measured by Google instead of by your app, which is a nice way to compare the two.

Doing it from the console instead

  1. Cloud Run → Deploy container → Service.
  2. Choose Continuously deploy from a repository (needs your code on GitHub) or Deploy one revision from an existing container image.
  3. Set region, Allow unauthenticated invocations, then under Container(s) → Variables add SECRET_KEY and ADMIN_PASSWORD, and under Revision autoscaling set maximum instances to 1.

Step 9 - Deploy the FastAPI version

Identical, from the other folder and with a different service name so both can run side by side:

cd app-fastapi

gcloud run deploy essentials-shop-fastapi \
  --source . \
  --region asia-southeast1 \
  --allow-unauthenticated \
  --max-instances 1 \
  --set-env-vars "SECRET_KEY=$SECRET,ADMIN_PASSWORD=choose-a-strong-one"

It also serves FastAPI's automatic API documentation at /docs. Open both Service URLs and compare: same pages, same behaviour, different framework.

Step 10 - Clean up (so you are not billed)

A scaled-to-zero service costs almost nothing, but the stored container images do cost a little, so remove what you do not need.

# delete the services
gcloud run services delete essentials-shop --region asia-southeast1
gcloud run services delete essentials-shop-fastapi --region asia-southeast1

# delete the stored images (the repository that --source created)
gcloud artifacts repositories delete cloud-run-source-deploy --location asia-southeast1

# or remove everything at once by deleting the whole project
gcloud projects delete ict239-shop-yourname

Troubleshooting

SymptomLikely cause and fix
The user-provided container failed to start and listen on the port defined by PORT=8080The app crashed at start-up or listens on 127.0.0.1. Read the logs (Step 8); look for an ImportError/ModuleNotFoundError or a missing package in requirements.txt. Check the CMD uses 0.0.0.0 and $PORT.
Browser shows 403 Forbidden from Google before the shop loadsThe service is private. Run gcloud run services add-iam-policy-binding essentials-shop --region asia-southeast1 --member=allUsers --role=roles/run.invoker. If an organisation policy blocks allUsers, use a personal Google account/project.
API [run.googleapis.com] not enabled or billing account ... not foundRedo Step 4, and make sure Step 3 linked billing to this project (gcloud config get-value project).
Build fails with PERMISSION_DENIED on Cloud Build or Artifact RegistryWait a minute after enabling the APIs and retry; make sure you are Owner/Editor of the project.
"400 Bad Request - The CSRF session token is missing" (Flask) or "Invalid or missing CSRF token" (FastAPI)The session cookie was lost, usually because the container restarted and SECRET_KEY was not set, so the old cookie no longer verifies. Set SECRET_KEY; reload the form page and submit again.
Registered user or cart suddenly goneContainer was recycled (idle scale-to-zero or redeploy). Expected with in-memory data. See Step 0.
Admin traffic looks lower than the Cloud Run Metrics tabYour app ignores static files, /healthz and the admin page's own polling on purpose.
Page loads without styling, links point to http://(FastAPI) the proxy flags are missing from the uvicorn command, so the app thinks it is on plain HTTP.
Deploy command is slow every timeNormal for --source (2-4 min). Keep COPY requirements.txt + pip install before COPY . . so the dependency layer is cached.

Extra challenges

  1. Add a .gcloudignore or tweak .dockerignore and see how the upload shrinks.
  2. Add a new product to products.json, redeploy, and use gcloud run revisions list to confirm the new revision is serving.
  3. Move ADMIN_PASSWORD into Secret Manager and attach it with --set-secrets ADMIN_PASSWORD=admin-password:latest.
  4. Add a "unique visitors" tile to the admin page (hint: a set() of session ids in TrafficLog).
  5. Replace the in-memory carts with Firestore so they survive restarts, then raise --max-instances.
